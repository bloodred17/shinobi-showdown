# Technical research

Define the decision the research must support and what evidence would change it. Prefer existing repository facts and installed-version documentation before broad searches. Use only available approved read tools; absent network access is a limitation, not permission to invent current facts.

1. Separate facts to establish, assumptions and viable options. Include an alternative that challenges the initial preferred approach.
2. Read original documentation, source or studies before citing them. Record relevant versions and dates. Search snippets are leads, and repeated accounts of one source are not independent corroboration.
3. Compare options against the actual constraints: behavior, compatibility, operational cost, verification and available tools. Do not optimize a dimension the user did not ask to trade away.
4. Resolve important contradictions or expose them as uncertainty. An executable experiment requires an approved environment; source reasoning is not benchmark evidence.
5. Present the recommendation, supporting citations, rejected options and conditions that would change the conclusion. Stop when more searching is unlikely to affect the decision.

Output: a decision-ready research note, not a new feature scope. If persistence is requested, use the approved artifact location and include source links needed by a fresh worker. The note informs the specification; it cannot silently replace an explicit user choice.
