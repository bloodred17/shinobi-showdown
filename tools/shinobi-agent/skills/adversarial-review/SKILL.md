# Adversarial review

Define the artifact, original requirements, disputed claims and candidate identity. Use only explicitly configured reviewers and available runtime mechanisms; no fallback model, external CLI or new swarm is implied.

1. Give independent reviewers the same artifact and requirements without another reviewer's verdict or the author's preferred conclusion.
2. Require concrete findings: condition, affected location, impact and supporting source or reproducible evidence. Speculation must be labeled.
3. Compare findings by evidence, not vote count. Combine duplicates without treating repeated wording as independent corroboration.
4. Adjudicate each blocking concern: accept and correct; reject with counter-evidence; or retain as unresolved with the observation needed to decide it.
5. Verify the correction on the current candidate and stop within the contract's budgets. Product disagreement or scope change returns for user direction.

Output: independent findings and explicit dispositions. If the environment only supports one review, report that limitation. Never manufacture model diversity or treat consensus as proof of correctness.
