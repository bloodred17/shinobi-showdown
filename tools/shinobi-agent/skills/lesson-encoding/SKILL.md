# Lesson encoding

Start with the evidenced failure and the repeated decision that caused it. Ask whether a deterministic condition can distinguish correct from incorrect behavior.

- If the invalid state can be prevented by an interface or type, prefer that structural boundary.
- If the failure can be reproduced reliably, use a targeted test or validation check with a useful diagnostic.
- If judgment is necessary, improve the relevant skill's trigger, decision criteria and example.
- If the knowledge is background rationale, keep it in a discoverable reference or decision record rather than every prompt.

Compare false positives, maintenance cost and the risk of encoding an accidental convention as a requirement. Preserve legitimate exceptions through explicit inputs or scoped applicability rather than encouraging bypasses.

Output: a justified recommendation, responsible location and validation case. Implement through an approved maintenance task such as `structural-correction` or `skill-improvement`. The existence of a lesson does not authorize changes to an active run's rules or every project in the workspace.
